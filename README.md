# dotfiles

## 適用

```sh
./install.sh <role>-<os>   # 例: ./install.sh work-macos / ./install.sh personal-linux
```

`role` は `work` か `personal`、`os` は `macos` か `linux`。`--files-only` を付けると、dotfiles を書き出すだけで、パッケージのインストール（macOS の `brew bundle`）はしない。

## 構成

各ディレクトリはホームディレクトリと同じ構成で、`install.sh` が次の順に重ねて `~` に書き出す。

| 層 | 置くもの |
|---|---|
| `common/` | すべての環境で使う設定 |
| `os/<os>/` | OS に依存する設定（パス、コマンドの違い、Homebrew） |
| `role/<role>/` | 仕事用・個人用の違い（仕事の組織の git 設定、sbx） |
| `env/<role>-<os>/` | role と OS の組み合わせでしか使わない設定 |
| `local/` | コミットしない設定（後述） |

同じパスのファイルが複数の層にあれば、JSON は深くマージし、そのほかは連結する。TOML・YAML は連結すると壊れるので、1つの層にだけ置く。

`~` のファイルは生成物なので、設定はリポジトリ側で編集して `install.sh` を再実行する。アプリや手作業で `~` 側が書き換えられていると、`install.sh` はそのファイルを上書きせずに差分を表示する。残す変更をリポジトリに移してから再実行するか、`-f` を付けて上書きする。

`.claude/settings.json` は Claude Code が `/model` などで書き換えるので、`~` の既存の内容にリポジトリの内容をマージして書き出す。リポジトリには、環境を作り直したときに再現したいキーだけを書く。リポジトリから消したキーは `~` 側に残るので、手で消す。

## コミットしない情報

- 公開したくないが秘密ではない設定（仕事のメールアドレス、取引先の組織名、社内のホスト名）は `local/` に置く。`local/` は `.gitignore` で除外していて、ほかの層と同じく重ねて書き出す。git には残らないので、1Password の Secure Note などに控えておく。
- トークンやパスワードはファイルに書かず、1Password から実行時に読む（`op read "op://<vault>/<item>/<field>"`、`op run`）。`gh` のように資格情報を OS のキーチェーンに保存するツールは、その仕組みに任せる。
